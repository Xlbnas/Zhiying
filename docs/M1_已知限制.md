# 知影 M1 已知限制

> 冻结基线：`v0.1.0-m1-local`（2026-07-22）。以下是使用与继续开发前必须知道的边界。

## 1. Docker / 飞牛尚未实机验收

M1 的全部验收在 Windows 开发机（Node 24 + Next dev + tsx worker）完成。
Dockerfile / docker-compose 与契约逐条对应、`next build` 已验证，但**镜像未实际构建、容器未实际运行**。
飞牛部署后请按 `docs/M1_飞牛部署验收清单.md` 逐项验收（11 项），重点：本机磁盘约束、cgroup 限额生效、SIGTERM requeue。

## 2. Windows 无法完整验证 SIGTERM 优雅退出路径

Windows 无 POSIX 信号语义（taskkill / git-bash kill 均为强制终止），worker 的
`SIGTERM → abort renderMedia → requeueJob → 退出` 链路**未能在开发机端到端实测**。
已做的替代验证：`requeueJob` 原子操作函数级 PASS（running → queued，claim 字段全清）；
信号处理代码路径经审查完整。Docker/Linux 环境 `docker stop` 会真实触发该路径（清单 D2 项）。

## 3. 当前仍是 M1：不含 AI 能力

以下能力**故意不包含**（红线，见 `视频生成器_架构设计文档.md` §10）：

- 无 LLM / DeepSeek（llm_jobs 表已建，仅作 M2 预留，无消费者）
- 无 TTS（示例旁白为已有 `public/full/audio/FullCut_TTS.wav` 资产）
- 无 Research / Evidence / Sources
- 无工作流引擎（阶段状态机、Stepper、run-stage 均属 M2+）

## 4. 当前示例项目使用弗洛伊德 FullCut 数据

系统内唯一的验证数据集来自 `samples/FullCutScenes.json`（85 场景）+
`samples/FullCutSubtitles.json`（237 条字幕，由 import-sample 脚本显式携带）。
通用 Import API 只接受请求体中的数据，**不含任何隐式固定字幕/模板 fallback**；
导入其他项目需自备符合 `src/lib/scene-schema.ts` 的 JSON（及可选 subtitles 字段）。

## 5. 下一步是 M1-B 飞牛部署，不是 M2

按架构文档开发计划，M1 的完整验收路径包含「飞牛上跑通完整闭环」。
因此当前冻结点的下一步是 **M1-B：飞牛 NAS 部署验收**（清单见 `docs/M1_飞牛部署验收清单.md`），
通过后才进入 M2（工作流引擎 + LLM 接入）。
