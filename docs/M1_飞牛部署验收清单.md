# 知影 M1 飞牛部署验收清单

目标环境：飞牛 NAS（fnOS）+ Docker。部署操作步骤见 `DEPLOY.md`，本清单是**部署后的逐项验收**。
每项完成后在 `[ ]` 内打勾；任一 FAIL 先回到 DEPLOY.md §6 常见问题排查。

部署前置：`cp .env.example .env` → `docker compose build` → `docker compose up -d`。

## A. 构建与启动

- [ ] **A1. Docker image 成功构建**
  `docker compose build` 零错误完成；`docker images | grep zhiying` 可见 `zhiying:m1`。
- [ ] **A2. web / worker 两个 service 成功启动**
  `docker compose ps` 两个容器均 `running`；`docker logs zhiying-worker` 可见
  `starting, data dir: /app/data` → bundle 缓存检查 → 进入调度循环，无反复重启。

## B. 数据层

- [ ] **B1. SQLite 数据位于飞牛本机磁盘，不在 SMB/NFS**
  compose 中 `./data:/app/data` 的 `./data` 解析到飞牛本机卷（如 `/vol1/...`）；
  在 NAS 上 `df -T <项目目录>/data` 或 `mount | grep <路径>` 确认文件系统为 ext4/btrfs/xfs 等本地类型，**不是** cifs/nfs。
- [ ] **B2. WAL / busy_timeout / foreign_keys / synchronous 参数生效**
  `docker exec zhiying-web node -e "const D=require('better-sqlite3');const db=new D('/app/data/zhiying.db');console.log(db.pragma('journal_mode'),db.pragma('busy_timeout'),db.pragma('foreign_keys'),db.pragma('synchronous'))"`
  预期：`journal_mode=wal`、`busy_timeout=5000`、`foreign_keys=1`、`synchronous=1(NORMAL)`。
  （journal_mode 是持久属性，其余三条由应用每次连接时设置，以应用日志/行为为准亦可。）

## C. 功能闭环

- [ ] **C1. 项目列表可以打开**
  浏览器访问 `http://<NAS-IP>:3000` 正常渲染；`curl -s http://<NAS-IP>:3000/api/projects` 返回 200 JSON。
- [ ] **C2. Scene Editor 和 Player 可以预览**
  导入样例（`node scripts/import-sample.mjs`，NAS 上需把 `BASE_URL` 指向本机服务）→
  项目页左侧 85 个场景、右侧 Player 可播放、点击场景播放头跳转、字幕显示。
- [ ] **C3. worker 可以 claim render job**
  项目页点「导出成片」→ `docker logs zhiying-worker` 出现 `job <id> start: ... composition=ZhiyingFullCut`；
  `curl -s http://<NAS-IP>:3000/api/jobs` 可见 status 由 `queued` 变 `running`，progress 持续增长。
- [ ] **C4. 完整 MP4 可以生成和下载**
  `/jobs` 页任务变「已完成」→ 点「下载 MP4」成功下载；
  `ffprobe` 验证：h264 1920×1080@30fps、时长约 612s、含 AAC 音轨。

## D. 资源与韧性

- [ ] **D1. cpus: 4 与 mem_limit: 6g 实际生效**
  `docker inspect zhiying-worker | grep -E 'NanoCPUs|Memory'` 应为 `4000000000` / `6442450944`；
  渲染期间 `docker stats zhiying-worker` 观察 CPU 不超过 400%、MEM 上限 6GiB。
- [ ] **D2. docker stop 时 running job 被 requeue**
  渲染进行中 `docker stop zhiying-worker`（默认 10s 内 SIGTERM）→
  worker 日志出现 `received SIGTERM` / `requeued due to shutdown`；
  `curl -s http://<NAS-IP>:3000/api/jobs` 确认该 job 回到 `queued`（而非卡在 running）；
  `docker compose start worker` 后 job 被重新 claim 并最终 succeeded。
- [ ] **D3. 容器重启后项目、Job、输出历史仍存在**
  `docker compose restart`（或 `down` 后 `up -d`）→
  项目列表仍有已导入项目；`/jobs` 仍有历史任务；已成功任务仍可下载 MP4。
