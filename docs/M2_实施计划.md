# 知影 M2 实施计划（Topic → Scenes 工作流引擎）

> 冻结基线：`v0.1.0-m1-local`。M2 目标：把「FullCutScenes.json → 视频」扩展为「主题 → … → Scenes JSON → M1 Player/Renderer」。
> 开发分支：`m2-workflow-engine`。每个子阶段：实现 → 测试 → 验收 → 独立 commit → push → 停止。M2 全部验收前不 merge main。
> 飞牛 Docker 部署验收延后，非 M2 前置。不接入 TTS/Sources/M3 编辑器。

## 1. 总体设计

### 1.1 范围

严谨模式 10 个主生产阶段：

```
project_definition → research → evidence → argument_tree → script_v1 → script_v2
→ narration_beat_map → visual_breakdown → shot_list → scenes
```

Pilot/FullCut 渲染继续走 M1 链路。**不做**：TTS、真人 VO、Sources 上传/解析 UI、自动素材搜索、BGM/SFX、M3 Scene Editor、拖拽 Timeline、自由图层编辑、飞牛 Docker 正式部署。Sources 架构预留接口，完整功能 M4。

### 1.2 数据模型（新增 3 表 + M1 表零结构变更）

```sql
-- 阶段状态机（每项目 10 行）
project_stages(
  project_id TEXT REFERENCES projects(id),
  stage TEXT NOT NULL,               -- 10 阶段枚举
  status TEXT NOT NULL DEFAULT 'not_started',  -- not_started/generated/edited/locked/stale
  active_version INTEGER,            -- 当前展示/编辑版本
  locked_version INTEGER,            -- 锁定版本（null=未锁）
  updated_at TEXT NOT NULL,
  PRIMARY KEY (project_id, stage)
);

-- 版本快照（自动保存 ≠ 覆盖唯一副本；回滚 = 复制旧版为新版本）
project_versions(
  id TEXT PRIMARY KEY,
  project_id TEXT NOT NULL REFERENCES projects(id),
  stage TEXT NOT NULL,
  version INTEGER NOT NULL,          -- 每 (project_id,stage) 递增
  content_json TEXT NOT NULL,        -- Markdown 文本或 JSON 字符串
  source TEXT NOT NULL,              -- ai_generate | manual_edit | repair | rollback
  prompt_version TEXT,               -- 关联 Prompt Registry 版本
  model TEXT,                        -- 生成模型（人工编辑为 null）
  job_id TEXT,                       -- 来源 llm_job（可空）
  note TEXT,
  created_at TEXT NOT NULL
);

-- 逐请求成本快照（架构 §6.2，旧调用永不重算）
llm_usage(
  id TEXT PRIMARY KEY,
  project_id TEXT, stage TEXT, job_id TEXT, request_id TEXT,
  provider TEXT NOT NULL, model TEXT NOT NULL,
  input_tokens INTEGER, cached_tokens INTEGER, output_tokens INTEGER,
  price_cache_hit_per_m REAL, price_cache_miss_per_m REAL, price_output_per_m REAL,
  cost_cny REAL, prompt_version TEXT, created_at TEXT NOT NULL
);
```

- M1 `llm_jobs` 表契约字段已齐全，**零改动直接启用**。
- `projects` 表仅更新 `current_stage` 列值，无结构变更。
- `artifacts` 表保持 M1 语义（scenes/subtitles/render_output）；**scenes 阶段 locked 时**把锁定内容同步写入 `artifacts(kind='scenes')`，M1 渲染链零感知。

### 1.3 状态机规则（src/lib/workflow/）

- `not_started → generated`（run-stage 成功）→ `edited`（人工编辑）→ `locked`（lock-stage）
- 上游未 locked → run-stage 返回 409（含首个未锁上游名）
- 编辑 locked 阶段：PATCH 需 `confirmStale:true` → 服务端将**全部下游**置 `stale`（locked_version 保留可查）
- `stale` 阶段必须 re-run 生成新版本后才能再次 lock
- 重新生成/编辑/回滚都产生新 version（active_version 指向新版；locked_version 不变直至重新锁定）

### 1.4 LLM Provider 层（src/lib/llm/）

```ts
interface LLMProvider {
  name: string;
  generate(input: {model: string; system: string; user: string; jsonMode: boolean}):
    Promise<{text: string; requestId: string;
             usage: {inputTokens: number; cachedTokens: number; outputTokens: number}}>;
}
```

- `deepseek.ts`：OpenAI 兼容 `POST /v1/chat/completions`，`DEEPSEEK_API_KEY` 走环境变量（永不入库/入 git）；模型 `deepseek-v4-flash` / `deepseek-v4-pro`；超时 + 单次重试（网络错误）+ 结构化错误。
- `mock.ts`：**MockLLMProvider**——按 stage 返回预置 fixtures（合法 Markdown/JSON），带确定性 token 计数；`LLM_PROVIDER=mock` 为开发/测试默认，状态机/DB/UI 测试零成本。
- **Mock 安全规则（M2-A 补充约束）**：mock 只允许在开发/测试环境**显式**使用；当 `NODE_ENV=production` 且 `LLM_PROVIDER=deepseek` 时，若缺少 `DEEPSEEK_API_KEY` 必须启动即报 `CONFIG_ERROR` 并拒绝 LLM 调用，**不得静默降级为 mock**（防止生产环境悄悄产生假数据）。非 production 且未配置 API Key 时可降级 mock，但必须日志警告。
- 模型分配配置：`stage-models.ts` 集中常量表（默认：argument_tree/script_v1/script_v2 → Pro，其余 → Flash），**不硬编码进 UI**；预留环境变量级覆盖 `LLM_STAGE_MODEL_<STAGE>`。

### 1.5 Prompt Registry（src/lib/prompts/）

- 每阶段一个模块：`{stage, promptVersion, outputKind: 'markdown'|'json', system, buildUser(input), zodSchema?}`。
- 内容产品化自 `03_通用总控提示词`：全局原则（研究/脚本/视觉/MG）抽为共享 system 片段，阶段指令来自对应 PHASE 段；变量插值（TOPIC/CORE_QUESTION/上游产物摘要），**不是整份 Markdown 塞入**。
- `promptVersion` 每模板常量（如 `research@1.0`），写入 project_versions 与 llm_usage——历史生成永远可溯源。
- 修改 prompt = 提升 promptVersion，旧版本模板保留不删。

### 1.6 结构化输出 + 有限 Repair

- `outputKind:'json'`：**scenes**（对齐 scene-schema，进渲染链必须）+ evidence / argument_tree / shot_list（条目/树结构，zod 校验）。
- `outputKind:'markdown'`：project_definition / research / script_v1 / script_v2 / narration_beat_map / visual_breakdown（人工编辑友好，保持原工作流形态）。
- Repair 流程：parse → zod validate → 失败则携带 issues 追问，**最多 2 次 repair**（含首次共 3 次调用，每次都记 llm_usage）→ 仍失败则 llm_job `failed`（error_code=`VALIDATION_FAILED`，完整 issues 存 error_message 供 UI 查看）。
- scenes 量级风险：85 场景一次生成易截断 → **按章节分批**（每批 ≤2 章）逐批校验合并，批次间共享前批场景 ID 摘要。

### 1.7 Stage API

| 路由 | 方法 | 行为 |
|---|---|---|
| /api/projects | POST | 新建项目（topic/core_question/参数）+ 初始化 10 阶段行 |
| /api/workflow/run-stage | POST | 状态机校验 → 创建 llm_job → 202 {job} |
| /api/workflow/lock-stage | POST | 锁 active 版本；scenes 阶段同步 artifacts(kind='scenes') |
| /api/projects/:id/stages | GET | 10 阶段状态 + active/locked version + 最近 job |
| /api/projects/:id/stage/:stage | GET | active 版本内容 |
| /api/projects/:id/stage/:stage | PATCH | 人工编辑 → 新版本（source=manual_edit）；locked 阶段需 confirmStale → 下游置 stale |
| /api/projects/:id/stage/:stage/versions | GET | 版本列表（元信息） |
| /api/projects/:id/stage/:stage/rollback | POST | 复制指定版本为新 active（source=rollback） |
| /api/jobs | GET | 扩展返回 `{jobs, llmJobs}`（render 部分 M1 兼容不变） |

### 1.8 Worker 兼容（单调度器扩展，render 机制零破坏）

- `claimNextAnyJob()`：BEGIN IMMEDIATE 内对 llm_jobs + render_jobs 按 queued_at 全局 FIFO claim（保持「任何时刻只跑一个」）。
- llm executor：payload(projectId,stage) → registry 取模板+上游产物注入 → provider.generate → parse/validate/repair → 写 project_versions + project_stages(generated) → usage 落库 → complete。
- recoverStaleJobs / heartbeat / cancel / retry 语义扩展到 llm_jobs；render executor 原样保留；M1 render 回归脚本持续可跑。

### 1.9 UI（zhiying-ui-design，非临时后台）

- `/project/[id]` 工作台重构：顶部 **Workflow Stepper**（10 阶段，locked/current/generated/edited/stale/not_started/failed 七态视觉 + 阶段连接线为视觉主线）→ 下方阶段面板（查看渲染 Markdown/JSON、编辑、重新生成、锁定、版本历史抽屉）；scenes locked 后保留 M1 Scene 列表 + Player + 导出。
- `/` 项目列表：新建项目入口（topic + core_question + 时长/平台/受众表单）+ 项目卡片增加阶段进度与累计成本（来自 llm_usage）。
- `/jobs`：增加 LLM 任务区块（阶段、模型、状态、成本）。
- 1366/1440/1920 宽度验收。

## 3. M2 架构影响摘要

1. **新增表**：project_stages、project_versions、llm_usage（3 张；幂等 CREATE，不动 M1 四表结构）。
2. **M1 表修改**：零结构修改。projects.current_stage 仅值更新；llm_jobs 从「建而不用」转为正式消费；artifacts 仅新增 scenes 同步写入路径。
3. **Worker 兼容**：单调度循环内 `claimNextAnyJob()` 对两表按 queued_at 全局 FIFO 原子 claim；llm/render 双 executor 分流；recover/heartbeat/cancel/retry 语义对 llm_jobs 对齐复用；render 链路代码零改动。
4. **Stage 状态存储**：project_stages 表（project_id+stage 主键，status/active_version/locked_version）。
5. **Artifact/Version 对应**：阶段产物全部进 project_versions（stage+version 递增）；artifacts 仅承载渲染链三类对象（scenes/subtitles/render_output），scenes locked 时由 versions 同步派生。
6. **Prompt 版本化**：Prompt Registry 每阶段模板带 promptVersion 常量，写入 project_versions.prompt_version 与 llm_usage.prompt_version；改 prompt=升版本号，旧模板保留。
7. **LLM Provider 替换**：统一 LLMProvider 接口 + `LLM_PROVIDER` 环境变量选择；新 Provider 实现接口即可注册，不动 executor。
8. **Mock 用于测试**：MockLLMProvider 按 stage 返回预置合法 fixtures（含确定性 usage），状态机/DB/API/UI 全链路零成本测试；开发默认 mock，真实 API 需显式配置。
9. **M1 持续回归**：verify-roundtrip 682、render job succeeded（弗洛伊德旧项目）、worker 六机制、tsc、next build、帧一致性抽查——每个 M2-X 的 checkpoint 条件。**回归分级（M2-A 补充约束）**：M2-A/B/D 使用轻量 Remotion smoke（renderStill 抽帧 + round-trip + build，不做全片渲染）；M2-C/E/F 才进行完整 Full Render 回归。
10. **最大 5 个实现风险**：
    1. Prompt 产品化拆解决定生成质量——总控提示词原为整段长上下文，拆成阶段模板+上游注入后输出质量可能退化（对策：M2-C/D 每阶段 DeepSeek 实测校准，而非闷头全写完）。
    2. scenes 全量 85 场景 JSON 一次生成易截断/校验失败（对策：按章节分批+repair 上限+失败现场可查）。
    3. 结构化 vs Markdown 的形态划分若失误会让中间产物难编辑（对策：§1.6 明确二分，只有进渲染链/树条目才 JSON）。
    4. 单调度下 6 分钟渲染会阻塞 LLM job（对策：接受 FIFO 并在 UI 明示排队；不引入并发，保架构红线）。
    5. DeepSeek v4 API 未实测（模型名/usage 字段/价格口径以架构文档为准，需 M2-B 一次真实 smoke 证实；失败则 mock 兜底不阻塞）。
