## 1. 前置依赖：public 资产（modern vs legacy，M3-E 后重新分类）

**Modern Production Final Workflow 不依赖 legacy public audio**（M4-C2A-R2 起生效）：

- 正式 Final Render 的 narration 是 **runtime 生成物**：worker 将当前
  Narration Audio Artifact staging 到 `runtime-audio/{projectId}/{artifactId}.wav`
  并随 bundle 提供（sha256 校验后 renderMedia）——不是
  `public/full/audio/FullCut_TTS.wav`。
- 正式 Final props 固定 `audio.bgm=null`、`audio.sfx=null`（frozen M3-E contract）。
- Modern production 必需的 public 静态资产只有 **visual track 引用的静态图片**
  （当前为 `public/pilot/images/*.jpg`），已就位。
- 因此 legacy 六个历史 WAV（`public/full/audio/*`、`public/pilot/audio/*`）
  缺失**不阻塞** modern Final Workflow deployment。

**Legacy M1 / demo 资产（OPTIONAL / NOT RECOVERED）**：

- `public/full/audio/`（FullCut_TTS/BGM/SFX.wav）与
  `public/pilot/audio/`（Pilot_BGM/SFX/VO.wav）六个原始 WAV 已确认丢失
  （Feiniu 全盘、开发机、VPS、Git 历史均无候选，原件仅存于旧开发机）。
- 影响仅限：Legacy `PilotCutV1` / `FullCutV1` composition 的 defaultProps /
  Studio demo 无法恢复原始音频体验（KNOWN LEGACY DEGRADATION）。
- 不得生成假资产冒充、不得从网络下载替代、不得用当前 IndexTTS2 新音频冒充
  历史 narration。若旧开发机恢复，可按原 bytes 另行恢复。

## 2. M4-C 管理员步骤

### 2.1 网络（一次性）

```bash
docker network create zhiying-tts-net   # 普通 NAT bridge，非 --internal（M4-A frozen）
```

### 2.2 宿主目录

```bash
mkdir -p /vol1/1000/docker/zhiying/{data,public,voices}
# owner 必须允许容器 uid 1000：data RW；public/voices read+traverse。禁止 chmod 777。
```

- `public/`：modern production 仅需 visual track 静态图片（`pilot/images/`）；
  legacy `full/audio` + `pilot/audio` 为 OPTIONAL（见 §1 分类，缺失不阻塞）
- `voices/`：拷入 voice reference WAV，并生成 production registry（下节）

### 2.3 production voice registry

```bash
cd /vol1/1000/docker/zhiying
sha256sum voices/default-v1.wav
# 按 services/indextts2-api-adapter/voice-registry.example.json schema 写
# /vol1/1000/docker/zhiying/voice-registry.json（referenceSha256 填实测值；
# speakerName 建议 zhiying-default-1-<sha256前12位>，仅为 readable label）
```

### 2.4 tts-stack 修改（indextts2 网络迁移）

备份后修改 `/vol1/1000/tts-stack/docker-compose.yml` 的 **indextts2**（仅此服务）：

```yaml
  indextts2:
    # network_mode: host        # ← 删除
    networks:
      - zhiying-tts-net
    ports:
      - "127.0.0.1:8002:8002"   # host admin/debug only；LAN 不可达
      - "7870:7870"             # WebUI 现状维持（M4 后续单独决定）
    healthcheck:
      test: ["CMD", "curl", "-f", "http://127.0.0.1:8002/health"]
      interval: 30s
      timeout: 10s
      retries: 5
      start_period: 120s
# 文件末尾：
networks:
  zhiying-tts-net:
    external: true
```

- 模型 bake 在镜像内，bridge 迁移不影响运行；`outputs/`（含 speaker_cache）
  volume 不动，recreate 不丢数据。
- qwen3-tts / cosyvoice3 保持 host network 不动。
- recreate indextts2（TTS 短暂停机）。

### 2.5 部署 Zhiying stack

```bash
cd /vol1/1000/docker/zhiying   # repo checkout（或直接放置 compose + build context）
cp .env.example .env.production  # 填 DEEPSEEK_API_KEY / ZHIYING_HOST_* / ZHIYING_RELEASE_TAG；chmod 600
# ZHIYING_RELEASE_TAG = 当前经过 review / CI 的 approved production deployment
# commit short SHA（历史：M4-B frozen = 23a675f；M4-C hotfix SHA 亦可。
# 禁止 latest；rollback = 将 ZHIYING_RELEASE_TAG 改回上一 release tag 后重新 up -d）
export ZHIYING_RELEASE_TAG=<approved-deployment-short-sha>
docker compose -f docker-compose.production.yml --env-file .env.production build
docker compose -f docker-compose.production.yml --env-file .env.production up -d
```

进程模型（M4-B frozen）：

```
web    : tini → node node_modules/next/dist/bin/next start
worker : tini → node --import tsx src/worker/index.ts（loader 进程内，无 shim 链）
docker stop → SIGTERM 直达 worker handler → 当前 job abort+requeue → bye.
（stop_grace_period 60s）

已知残留（frozen src/Remotion 句柄）：render/bundle 活动后 node 进程在
bye. 之后可能不自然退出，grace 到期被 SIGKILL——发生在优雅契约
（requeue + bye.）完成之后，job 状态已安全持久化，无数据影响；
后续如需根治应在 M3 worker 退出路径显式 process.exit（属 frozen src，另议）。
```

启动顺序语义（frozen）：

```
indextts2 未就绪 → adapter 进程存活但 unhealthy → worker 不启动
indextts2 就绪   → adapter healthy（upstream + registry + SHA-256 全过）→ worker 启动
```

### 2.6 验收（全部必须实测）

```bash
# 8002：host loopback 可达，LAN 不可达
curl -s http://127.0.0.1:8002/health                       # PASS
# 同网段另一设备：
curl -m 5 http://192.168.31.56:8002/health                 # 必须 FAIL/unreachable
curl -m 5 http://192.168.31.56:7870/                       # PASS（现状维持）

# adapter / worker 链路
docker inspect --format '{{.State.Health.Status}}' indextts2-adapter   # healthy
docker logs zhiying-worker | head                                      # starting

# 反向代理 → 127.0.0.1:3210 → zhiying-web（fnOS nginx 为宿主进程，可访问宿主 loopback）
curl -s http://127.0.0.1:3210/api/projects                 # 2xx
```

**若 Docker daemon 实际行为与 ports 声明不符（如 8002 仍 LAN 可达）：
STOP、rollback（§3）、报告。禁止用防火墙临时糊。**

## 3. Rollback

- Zhiying 版本回滚：`.env.production` 的 `ZHIYING_RELEASE_TAG` 改回上一 release
  tag → `docker compose -f docker-compose.production.yml --env-file .env.production up -d`
  （镜像 tag 即版本锚点，禁止 latest 使回滚可精确指定）
- tts-stack：恢复修改前备份的 compose 文件 → `docker compose up -d indextts2`
  （host network 复原；数据卷全程未动）
- Zhiying stack：`docker compose -f docker-compose.production.yml down`，
  不影响 tts-stack；data/public/voices 宿主目录保留

## 4. 运维注意事项

- **单 Worker 不变量**：scheduler 仅在 worker 进程；无代码级锁，且 stale job
  recovery 会让多 worker 互相回收。严禁 `--scale zhiying-worker=N`（N>1）。
- `switch.sh`（tts-stack）切换 TTS 服务会停 indextts2 → adapter ready=false →
  TTS job 响亮失败（fail-closed 设计内行为），worker 随 depends_on 不再重启就绪。
- 备份：`data/`（SQLite WAL + artifacts）与 `public/`、`voices/` 需备份；
  `data/bundle-cache/` 可重建不备份；tts-stack `outputs/`（speaker cache）建议备份。
- 宿主 3000 端口已被占用 → web 固定发布 `127.0.0.1:3210`。
- 镜像构建：Feiniu 为 x86_64；在 Mac（arm64）上构建的镜像**不可直接用于
  Feiniu**——在 Feiniu 上 build，或 `docker buildx build --platform linux/amd64`。
